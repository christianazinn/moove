# agents/ - Agent worker (Node/TS)

Lanes: backend (vision, pricing, sort, fraud) and commerce (x402 spending, eBay listing, approvals, Visa).

- A long-running Node process, connected to SpacetimeDB as a client via generated bindings in `src/module_bindings/` (never hand-edit them).
- Pattern: subscribe to rows that need work, do the work, write results via reducers. Writes never bypass reducers.
- **Every agent step writes an `agentEvents` row** (plan / tool_call / result / payment / approval / error).
- One file per external service in `src/integrations/` (anthropic, apify, x402, ebay, visa, auth0), each behind an interface with a **labeled simulated implementation** for demo fallback. `visa.ts` stays a stub until the Visa Starter Pack is out.
- Agents live in `src/agents/` (vision, pricing, sort, listing, buy, fraud).
- Spending: enforce `AGENT_SPEND_CAP_USDC`. Purchases or listings above the user's `approvalThresholdCents` require an `approvals` row and an Auth0 async authorization (CIBA) before they proceed.
- Models come from env (`MODEL_VISION`, `MODEL_FAST`, `MODEL_AGENT`).
- Cache real Apify responses into `fixtures/` so the demo can replay them if live calls fail. Label any replay.
- Config comes from `.env.local` (see root `.env.example`).
- x402/CDP, Apify, eBay, Auth0 for AI Agents and Visa APIs change often, so check current docs first.

## What's here
- `src/upload.ts`: file store on `UPLOAD_PORT` (8787). `POST /upload` takes a raw body with Content-Type `image/jpeg|png|heic|webp`, `model/vnd.usdz+zip` or `application/json`, and returns `201 {"url": ...}`. `GET /files/<name>` serves it. URLs use `PUBLIC_UPLOAD_BASE_URL`, so set it to your laptop's LAN IP when testing from phones. Store the returned URLs via `import_scan` / `add_item_photo`.
- `src/integrations/anthropic.ts`: `structuredCall({model, system, text, images, schema})` returns a zod-validated object (beta `parse` + server-side refusal fallbacks). `loadImage(url)` fetches and base64-encodes an image, so the API never has to reach LAN URLs.
- `src/agents/vision.ts` (#5): items with `details_status = pending` and at least one photo go to Claude vision, then `set_item_details`. Adding a photo re-queues the item. Unloadable photos are skipped.
- `src/agents/listing.ts` (#11): items with `disposition = sell`, details done and pricing done/failed get a Claude-written listing (price clamped to 70-130% of the pricing estimate's range). Drafts at or under the owner's `approval_threshold_cents` post right away; above it (or threshold -1) it calls `request_approval` and waits for `decide_approval`. An approval only counts if its amount still matches the listing price.
- `src/integrations/ebay.ts`: `EbayPoster` interface with two backends, chosen once at startup by `chooseEbay()`. `sandboxEbay` (#32) posts for real over plain fetch (Sell Inventory API: inventory item -> offer -> publish, reusing the SKU's offer on retry). It picks a leaf category by name from the marketplace's live category tree (no hardcoded IDs; `getCategorySuggestions` doesn't work in sandbox) and fills every required item specific from `getItemAspectsForCategory`. It's used only when every `EBAY_*` key from `scripts/ebay-setup.ts` is set; photos must be public https (or `EBAY_FALLBACK_IMAGE_URL`). Otherwise `simulatedEbay` logs the same steps with delays and writes `uploads/listing-<id>.html`, served at `/files/` (html is served, never accepted as an upload). A listing posts the way it was drafted (`simulated` never lies). `LISTING_SIM_SOLD_AFTER_SEC` > 0 flips posted simulated listings to `sold`.
- `scripts/ebay-setup.ts` (`npm run ebay:setup -- consent | token <url> | provision | check`): one-time seller setup that prints the `.env.local` lines (refresh token, business-policy opt-in, 3 policies, location).
- `src/integrations/x402.ts` + `src/payments.ts` (#7): `const rail = await paymentRail(conn)`, then `rail.paidFetch({owner, agent, purpose, refTable, refId, quotedUsdMicros}, url)` pays x402 endpoints from the `moove-agents` CDP wallet on Base Sepolia. It checks the per-agent budget (`AGENT_SPEND_CAP_USDC`) and per-call max (`X402_MAX_PER_CALL_USDC`) before signing, writes `record_payment` + `log_agent_event` rows, and throws `SpendRefusedError` (already logged) when over budget. With no CDP keys or `X402_SIMULATE=1` it is simulated: `quotedUsdMicros` is recorded with `simulated: true`. `npm run x402:wallet [-- --faucet]` shows or funds the wallet. `npm run x402:demo` makes one paid call. `npm test` runs the x402 tests.
- `src/paywall.ts` (#7): `createCompsPaywall(lookup)` returns an express app serving `GET /x402/comps?q=`, paywalled at $0.01 when CDP keys are set. The pricing agent (#6) can pass its Apify lookup and buy comps through it, so every pricing run makes a real testnet payment.
- `src/agents/approval.ts` + `src/integrations/auth0.ts` (#12): watches `approval` rows with status `pending`. With Auth0 configured (`AUTH0_DOMAIN`, `AUTH0_CIBA_CLIENT_ID`, `AUTH0_CIBA_CLIENT_SECRET`) and the owner's `user.auth0_sub` set, it sends a CIBA request (`/bc-authorize`, Guardian push, `requested_expiry=300`, binding message sanitized to Auth0's 64-char charset by `toBindingMessage`), polls `/oauth/token`, checks the `id_token` `sub`, then calls `decide_approval` with `approved`/`denied`. If the push expires, the request errors, or there is no Auth0 config / `auth0_sub`, the approval stays `pending` for the iOS Approvals inbox (which calls `decide_approval` itself). The worker only calls `decide_approval` with a gateway poll result (one function, `decideFromGateway`). `APPROVAL_SIM_AUTO_APPROVE_SEC` > 0 (demo only, off by default, ignored when Auth0 is configured) auto-approves after N seconds and labels every event simulated. Starts are capped at 4 per owner per minute (Auth0 allows 5). `APPROVAL_THRESHOLD_CENTS_DEFAULT` is the fallback threshold when an owner has no `user` row.
