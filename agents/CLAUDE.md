# agents/ - Agent worker (Node/TS)

Lanes: backend (vision, pricing, sort, fraud) and commerce (x402 spending, eBay listing, approvals, Visa).

- A long-running Node process, connected to SpacetimeDB as a client via generated bindings in `src/module_bindings/` (never hand-edit them).
- Pattern: subscribe to rows that need work, do the work, write results via reducers. Writes never bypass reducers.
- **Every agent step writes an `agentEvents` row** (plan / tool_call / result / payment / approval / error).
- One file per external service in `src/integrations/` (anthropic, apify, x402, ebay, visa, auth0, aitext), each behind an interface with a **labeled simulated implementation** for demo fallback. `visa.ts` stays a stub until the Visa Starter Pack is out.
- Agents live in `src/agents/` (vision, pricing, sort, listing, buy, fraud).
- Spending: enforce `AGENT_SPEND_CAP_USDC`. Purchases or listings above the user's `approvalThresholdCents` require an `approvals` row and an Auth0 async authorization (CIBA) before they proceed.
- Models come from env (`MODEL_VISION`, `MODEL_FAST`, `MODEL_AGENT`).
- Cache real Apify responses into `fixtures/` so the demo can replay them if live calls fail. Label any replay.
- Config comes from `.env.local` (see root `.env.example`).
- x402/CDP, Apify, eBay, Auth0 for AI Agents and Visa APIs change often, so check current docs first.

## What's here
- `src/upload.ts`: file store on `UPLOAD_PORT` (8787). `POST /upload` takes a raw body with Content-Type `image/jpeg|png|webp`, `model/vnd.usdz+zip` or `application/json`, and returns `201 {"url": ...}`. `GET /files/<name>` serves it. `GET /healthz` returns `200 {"ok":true}` for platform health checks. Hardened (#17): the body must match the declared type (magic bytes), `UPLOAD_MAX_BYTES` caps size (default 50 MB), EXIF/GPS/XMP/text metadata is stripped from JPEG/PNG/WebP (`src/imagemeta.ts`, keeps JPEG orientation), HEIC is refused with 415 (send JPEG), names are random UUIDs (`?name=` is ignored), no listing, `nosniff` + a CSP on served html. No auth on POST yet (waits on #1). Tests: `npm test`. URLs use `PUBLIC_UPLOAD_BASE_URL`, so set it to your laptop's LAN IP when testing from phones. Store the returned URLs via `import_scan` / `add_item_photo`.
- `Dockerfile`, `.dockerignore`, `fly.toml` + `docs/deploy.md`: hosted worker (DO Droplet / App Platform or Fly.io) with `/app/uploads` on a volume and the identity from the `SPACETIME_WORKER_TOKEN` secret. The image keeps dev deps (it runs through `tsx`). Writing the token file is best effort (`saveToken` in `src/spacetime.ts` logs on a read-only FS). `src/index.ts` exits on SIGTERM/SIGINT (node as container PID 1 would ignore SIGTERM). Never run two workers against one DB: stop the laptop worker first.
- `src/integrations/anthropic.ts`: `structuredCall({model, system, text, images, schema, effort?, maxTokens?, fallbacks?})` returns a zod-validated object (beta `parse` + server-side refusal fallbacks; pass `fallbacks: false` for Haiku, which has none). `loadImage(url)` fetches and base64-encodes an image, so the API never has to reach LAN URLs. **`LLM_REPLAY`** (`off`|`auto`|`replay`|`record`) records each answer to `fixtures/llm/<key>.json`, keyed by model + prompts + image hashes + output schema, and replays it (re-validated against the schema). Use `auto`/`replay` in tests and E2E runs so they don't spend the API budget.
- `src/agents/vision.ts` (#5): items with `details_status = pending` and at least one photo go to Claude vision, then `set_item_details`. Adding a photo re-queues the item. Unloadable photos are skipped; if none load, the error says why (e.g. host not allowed). At most `VISION_CONCURRENCY` (3) items are identified at once (the scan photographs every object). `setVisionDeps` swaps the photo loader and model call in tests (`test/vision.test.ts`).
- `src/agents/sweep.ts`: room photo sweep. When a scan gets `scan_photo`s (`sweep_status = pending`) and they stop arriving for `SWEEP_SETTLE_MS` (8 s), one `MODEL_VISION` call gets up to 6 photos plus the room's scanned objects (id, category, size). It returns `matches` (better names, brand, condition for RoomPlan boxes it can see, written via `apply_sweep_match`, which re-queues pricing on a rename) and `newItems` (things RoomPlan missed, via `add_sweep_item`). `vetSweep()` drops invented ids, confidence < 0.6, duplicates and junk, bounds sizes, and cleans every string. Text inside photos is treated as data. Injectable deps for tests (`setSweepDeps`).
- `src/agents/listing.ts` (#11): items with `disposition = sell`, details done and pricing done/failed get a Claude-written listing (price clamped to 70-130% of the pricing estimate's range). Drafts at or under the owner's `approval_threshold_cents` post right away; above it (or threshold -1) it calls `request_approval` (the module checks the amount equals the listing price) and waits for the owner's `decide_approval` or the worker's `record_ciba_decision`. `update_listing` is worker-only. An approval only counts if its amount still matches the listing price.
- `src/integrations/ebay.ts`: `EbayPoster` interface with two backends, chosen once at startup by `chooseEbay()`. `sandboxEbay` (#32) posts for real over plain fetch (Sell Inventory API: inventory item -> offer -> publish, reusing the SKU's offer on retry). It picks a leaf category by name from the marketplace's live category tree (no hardcoded IDs; `getCategorySuggestions` doesn't work in sandbox) and fills every required item specific from `getItemAspectsForCategory`. It's used only when every `EBAY_*` key from `scripts/ebay-setup.ts` is set; photos must be public https (or `EBAY_FALLBACK_IMAGE_URL`). Otherwise `simulatedEbay` logs the same steps with delays and writes `uploads/listing-<id>.html`, served at `/files/` (html is served, never accepted as an upload). A listing posts the way it was drafted (`simulated` never lies). `LISTING_SIM_SOLD_AFTER_SEC` > 0 flips posted simulated listings to `sold`.
- `scripts/ebay-setup.ts` (`npm run ebay:setup -- consent | token <url> | provision | check`): one-time seller setup that prints the `.env.local` lines (refresh token, business-policy opt-in, 3 policies, location).
- `src/integrations/x402.ts` + `src/payments.ts` (#7): `const rail = await paymentRail(conn)`, then `rail.paidFetch({owner, agent, purpose, refTable, refId, quotedUsdMicros}, url)` pays x402 endpoints from the `moove-agents` CDP wallet on Base Sepolia. It checks the per-agent budget (`AGENT_SPEND_CAP_USDC`) and per-call max (`X402_MAX_PER_CALL_USDC`) before signing, writes `record_payment` + `log_agent_event` rows, and throws `SpendRefusedError` (already logged) when over budget. With no CDP keys or `X402_SIMULATE=1` it is simulated: `quotedUsdMicros` is recorded with `simulated: true` (a non-2xx endpoint or a thrown fetch refunds the budget and logs `failed`, like real mode). `npm run x402:wallet [-- --faucet]` shows or funds the wallet. `npm run x402:demo` makes one paid call. `npm run x402:e2e` (needs a local `spacetime start` + `publish:local`) pays once as the worker and prints the `payment` + `agent_event` rows that landed, then checks that a non-worker's `record_payment` is rejected (exit 1 on failure). `npm test` runs the x402 tests. Every x402 `agent_event.data_json` has `rail: "x402"`, `outcome` (`paying`|`settled`|`failed`|`refused`), `simulated`, and the agent's `remainingUsdMicros` + `capUsdMicros` after that step (strings), plus `url`, `payee`, `amountUsdMicros` where known, `txHash`/`explorer` on settle and `refused: true` on refusals. **The pricing agent pays through it:** `src/integrations/paid-comps.ts` serves the comps paywall on `127.0.0.1:X402_PORT` (8402) and `index.ts` swaps in `paidCompsSource`, so every pricing run buys its comps for $0.01 (one `payment` row per item, `simulated: true` without CDP keys). On a refusal or any payment/HTTP failure it logs the fallback (`tool_call`) and calls Apify directly, so pricing never fails because of payments. The exception is a 502 "comps lookup failed" from the paywall: Apify already failed there, so it isn't run again and pricing fails the item. If the paywall can't start (port taken, CDP outage), `installPaidComps` logs it and the worker keeps pricing on direct lookups. `PRICING_PAY_X402=0` skips this and calls Apify directly.
- `src/paywall.ts` (#7): `createCompsPaywall(lookup)` returns an express app serving `GET /x402/comps?q=`, paywalled at $0.01 when CDP keys are set. The pricing agent (#6) can pass its Apify lookup and buy comps through it, so every pricing run makes a real testnet payment.
- `src/agents/approval.ts` + `src/integrations/auth0.ts` (#12): watches `approval` rows with status `pending`. With Auth0 configured (`AUTH0_DOMAIN`, `AUTH0_CIBA_CLIENT_ID`, `AUTH0_CIBA_CLIENT_SECRET`) and the owner's `user.auth0_sub` set, it sends a CIBA request (`/bc-authorize`, Guardian push, `requested_expiry=300`, binding message sanitized to Auth0's 64-char charset by `toBindingMessage`), polls `/oauth/token`, checks the `id_token` `sub`, then calls the worker-only `record_ciba_decision` with `approved`/`denied` and that `sub` (#42; the module rejects it unless it equals the owner's `user.auth0_sub`, and records `decided_via = 'ciba'`). The worker can't call `decide_approval` (owner-only). If the push expires, the request errors, or there is no Auth0 config / `auth0_sub`, the approval stays `pending` for the iOS Approvals inbox (which calls `decide_approval` itself). The worker only records a decision from a gateway poll result (one function, `decideFromGateway`). There is no simulated auto-approver any more: `APPROVAL_SIM_AUTO_APPROVE_SEC` is ignored with a warning. Starts are capped at 4 per owner per minute (Auth0 allows 5). `APPROVAL_THRESHOLD_CENTS_DEFAULT` is the fallback threshold when an owner has no `user` row.
- `src/integrations/apify.ts`: `lookupComps(query)` returns `{comps, replayed}` (same shape as `CompsLookup` in #7's paywall). It runs eBay sold listings and FB Marketplace actors (`APIFY_SOURCES`), with `maxItems` and `maxTotalChargeUsd` caps per run, and caches every query in `fixtures/comps/<slug>.json`. A cached hit comes back `replayed: true` and the event message says `[REPLAYED]`. Commit good real caches for demo items; never commit made-up ones.
- `src/agents/pricing.ts` (#6): items with `pricing_status = pending` are priced once vision is done/failed (or the item has no photos). The query is brand + name. The estimate is the median of comps within 3x of the median, scaled by condition, with low/high at the quartiles. `setCompsSource()` lets #7 route lookups through the x402 paywall. Comps go through `src/agents/comp-filter.ts` first, and only the kept ones are written with `add_comps` and estimated from. Items named only by a RoomPlan catch-all (`other`, `storage`, `unknown`, ...) with no brand wait for vision or a `rename_item` before pricing, so we never pay for junk comps. Lookups go through a queue (`PRICING_CONCURRENCY`, default 2, under Apify's 5-concurrent-run free-plan limit). Transient errors (concurrency/rate limits, 5xx, network) retry with backoff up to 3 attempts instead of failing. `PRICING_RETRY_FAILED=1` re-queues earlier failures on start.
- `src/integrations/visa.ts` + `src/checkout.ts` (#15): `visaCheckout(conn).purchase({owner, agent, purpose, merchant, refTable, refId, amountCents, thresholdCents, currentApproval, stillValid, consumerPrompt})` runs gate -> spend ledger (`VISA_SPEND_CAP_USD`, `VISA_MAX_PER_PURCHASE_USD`) -> authorization hold -> re-check approval + `stillValid` -> capture, or a reversal (void). It writes a `payment` row (rail `visa`, pending -> settled/failed) and an `agent_event` per step. `VISA_PROVIDER=acceptance` uses the CyberSource REST sandbox (HTTP Signature, `apitest.cybersource.com` only, Visa test card, no real money; rows `simulated: false`, event data `sandbox: true`) and never hides a broken integration: 401/403 and, with `VISA_PROVIDER=acceptance` set, missing keys fail the checkout with an `error` event. A 5xx/network error falls back to the labeled simulated backend only with `VISA_FALLBACK_SIMULATED=1` (or when no provider was set); otherwise it is a retryable failure (the buy agent retries up to 3 times, `BUY_RETRY_DELAY_MS`). Sandbox payment purposes start with `[Visa sandbox]`. With no `VISA_ACCEPTANCE_*` keys it is simulated (`simulated: true`, and every event message, including refusals and "Not charging yet", starts with `[SIMULATED]`; same on the simulated x402 rail). `vic` is a documented seam only.
- `src/integrations/deals.ts` (#15): `DealSource` interface, `fixtureDealSource()` serving hand-made `fixtures/deals.json` (labeled `sample data`; real cached Apify results say `cached replay`), `rankDeals` (price, condition, distance, card-checkout bonus), `sanitizeText` for scraped text. `src/integrations/deals-apify.ts`: `createDealSource(env)` picks live Apify search (FB Marketplace + eBay Buy It Now by default, Craigslist opt-in via `DEALS_APIFY_SOURCES`), caching runs in `.cache/deals/` (gitignored) and reading committed replays from `fixtures/deals-live-*.json`, then the sample data. Live and replayed results always carry the matching sample retail rows (labeled `sample data`) so every item has a card-checkout option. Rows in `fixtures/deals.json` with `"planted": true` are planted demo scams (still `sample data`, seller "Planted demo scam (not a real listing)"), served only for items whose name or category contains one of its `plantedFor` phrases as whole words, case and plurals ignored, and none of its `plantedExcept` words (`plantedMatches` in `deals.ts`; today one Zelle-only Aeron for desk/office/task/computer/ergonomic/gaming/swivel/mesh chairs, never dining chairs, armchairs or chair mats, scored 0.85 by the real fraud rules; `test/planted-deal.test.ts`). A list with no such chair gets no planted deal, and `pickDealsToWrite` always writes them, so the fraud block shows live. No FB seller names or eBay handles are stored. It is chosen in one line in `buy.ts`; at most `DEALS_SEARCH_CONCURRENCY` (2) searches run at once.
- `src/agents/shopping.ts` (#15): when a `new_home` row appears and the owner has no shopping items, Claude (`MODEL_AGENT`) lists what the rooms still need minus `keep` items (rule-based fallback), then `add_shopping_item`.
- `src/agents/buy.ts` (#15): open shopping items get deals searched, ranked and written (`add_deal`), and the best card-checkout deal recommended in an event (nothing is bought until the user chooses a deal; `BUY_AUTO_CHOOSE=1` makes the agent choose it). Before asking for approval it checks the card caps, so the user is never asked to approve a purchase that would be refused. For the chosen deal: fraud score >= `BUY_FRAUD_BLOCK` is skipped, marketplace sellers get a drafted message, card merchants go through Visa checkout. Above the owner's threshold it calls `request_approval` (kind `purchase`, ref = deal id) and waits; the approval must match the price and is re-checked before capture. The agent never calls `decide_approval` itself.
- `src/agents/sort.ts` (#8): `auto` items (never user-set ones) are sorted once pricing is done/failed and vision is done/failed (or no photos), and re-sorted whenever `nextSort()` finds the stored decision no longer matches `decide()` (vision, re-pricing, `set_fragile` or a rename changed it). `maybe_sentimental` items, even already-sorted ones, are parked as `undecided` with "possibly sentimental - your call"; clearing the flag re-sorts them. Pure rules, no model calls: `decide(item)` weighs `est_value_cents` against a moving cost of volume x `SORT_MOVE_USD_PER_M3` ($60/m^3, min $2, x1.5 if fragile). Worth less than the move: sell if >= `SORT_SELL_MIN_USD` ($25), else donate; worth < 1.25x the move: sell; otherwise keep. Poor condition: trash unless worth >= $25 (then sell). Beds/mattresses keep (trash if poor), cheap or unpriced clothing/books donate, unknown value keeps, built-ins (toilet, sink, ...) stay `undecided` with a reason. Reasons quote the numbers ("Worth ~$50 but ~$97 to move: sell"). Writes `set_auto_disposition` and one `sort`/`result` event per change. A re-sort doesn't withdraw a listing already drafted for an earlier `sell`.
- `scripts/seed-demo.ts` + `scripts/demo-room.ts` (`npm run seed:demo [-- --force] [-- --wait] [-- --maincloud]`): demo safety net. Connects as a normal user (token in `.user-token.<db>`, or `SEED_USER_TOKEN_FILE`), calls `register_user` + `import_scan` for a 9-item college bedroom ("Bedroom", home `old`, no photos so vision never runs) and flags the guitar sentimental. Refuses a maincloud URI without `--maincloud`. Skips if the user already has a Bedroom unless `--force`, prints the join code, and with `--wait` prints the worker's estimates. Every item's pricing query has a committed real cache in `fixtures/comps/`, so the room prices from replays with no Apify or Claude calls (`test/demo-room.test.ts` enforces it). `npm run comps:prefetch [-- --dry]` fetches any missing demo cache. Runbook: `docs/demo.md`.
- `src/agents/fraud.ts` (#18): every `deal` with `fraud_score = -1` is screened (after `FRAUD_SETTLE_MS` of quiet per shopping item, so a burst of deals is judged together) and gets `set_deal_fraud(deal_id, fraud_score, ai_text_score, reasons[])` plus one `fraud` `result` event with per-signal scores. No Claude calls. Five exported pure signals, each 0..1: `priceSignal` (vs. the median of the other deals for the shopping item, and cached comps for its name via `cachedComps()`, which never triggers an Apify run), `offPlatformSignal` (Zelle, Cash App, Venmo only, wire, gift cards, crypto, deposits, shipping only, email/text/phone in the title or seller_info), `newSellerSignal` (seller_info like "joined 2026", "0 ratings", "new account"; empty seller_info is mild), `duplicateSignal` (same link under a different title, or same title + price under different links/sources; retail catalog sources in `RETAIL_SOURCES` are exempt, since the same product legitimately repeats across shopping items and users), `aiTextSignal`. `combine()` is a weighted noisy-OR, `1 - prod(1 - WEIGHTS[k] * signal)`, with weights off-platform 0.85, duplicate 0.5, price 0.55, new seller 0.45, AI text 0.4: one payment ask alone crosses the buy agent's `BUY_FRAUD_BLOCK` (0.7, #40), a cheap price alone only reaches "some risk" (0.3). Reasons are short app-facing strings, strongest first; signals below their floor add no score, so every point has a reason. `fixtures/fraud-deals.json` is a planted test set with an answer key, checked by `test/fraud.test.ts` (all scams caught with the right reasons, 0 false positives). `test/fraud-agent.test.ts` drives the loop against a fake connection (settle batching, one screen per deal, scored rows skipped, detector and reducer failures).
- `src/integrations/aitext.ts` (#18): `AiTextDetector { name, score(text) -> 0..1 }`. `chooseAiTextDetector()` returns the Pangram-replication HTTP client when `PANGRAM_URL` is set, else null (deals keep `ai_text_score = -1`, no reason). Wire format: `POST $PANGRAM_URL`, `Content-Type: application/json`, optional `Authorization: Bearer $PANGRAM_TOKEN`, body `{"text": "..."}`, response `{"score": 0.93}` (higher = more likely AI). To adapt to a different service shape, edit only `toRequestBody()` / `parseScore()` (it already accepts `ai_score`, `probability`, `fraction_ai`, a bare number or `[{score}]`). Today the text is the deal title (deals have no description); titles under `FRAUD_AI_TEXT_MIN_CHARS` (20) are skipped. A detector failure logs a `fraud` `error` event and scores the deal without it. Scores >= 0.5 count toward fraud with a reason ("listing text may be AI-generated (0.62)", "likely" from 0.7).
- `src/agents/comp-filter.ts`: `filterComps(item, comps)` drops irrelevant comps in two stages: a free regex pre-filter (insert, parts, broken, wanted/ISO/WTB, bundle, lot of, replacement, unless the item's own name/category has that word), then `MODEL_FAST` (Haiku, effort low, 2048 max tokens) picks the indices to keep from the numbered titles+prices with a one-line reason. Titles are cleaned and fenced with `src/untrusted.ts` like the listing prompt (#17); out-of-range indices are ignored and the reason is cleaned and capped at 200 chars before it reaches events. Verdicts are cached in `fixtures/comps/<slug>.filter.json`, keyed by the item description (name, brand, category, material, dims, condition) + the comps it saw, so replays don't re-pay; the event says `[REPLAYED]`. If Claude errors (or keeps nothing) it falls back to the rule-filtered comps and logs an `error` event. Neither stage ever drops every comp. The pricing `tool_call` event says how many were dropped and why, and the `result` event has `dropped`. `PRICING_COMP_FILTER=0` turns the filter off, `=rules` skips Claude.
- `scripts/run-worker.sh`: supervisor for the live worker. It restarts `src/index.ts` whenever it exits (a crash, or the disconnect a maincloud republish causes), backing off up to 60 s in a crash loop. Run it with the same env as `npm start`. After a contract change, still `git pull && npm ci` first. With `PUBLIC_UPLOAD_BASE_URL_FILE=<file>` it re-reads the upload URL from that file on every start. The worker also exits by itself if its SpacetimeDB connection stays down for `WORKER_DISCONNECT_EXIT_SEC` (120 s), so a reconnect loop after the laptop sleeps becomes a clean restart.
- `scripts/tunnel.sh <port> <url-file>`: keeps a Cloudflare quick tunnel to the worker's upload port alive. It writes the URL to `<url-file>`, health-checks `<url>/healthz` every 60 s, and after 3 failures restarts cloudflared (a new URL) and kills the worker on `<port>`, so run-worker.sh restarts it with the new URL, which it announces in `service_config`.
- `src/agents/sam3d.ts` + `src/integrations/sam3d.ts` (#65): items with `model_status = pending`, a photo, vision done/failed and no captured model get a 3D model from **Meta SAM 3D Objects** on fal.ai (`fal-ai/sam-3/3d-objects`, queue REST API, `export_textured_glb`). It sends the latest photo as a data URI and the item name as the segmentation prompt, writes the GLB to `uploads/<uuid>.glb` (served at `/files/`, never accepted as an upload), then calls `set_item_model(url, 'sam3d')`. About $0.02 per item, capped by `SAM3D_MAX_USD` per worker run (default $1), `SAM3D_CONCURRENCY` (2). Without `FAL_KEY` it's off and items stay pending. Object Capture models from the phone always win (enforced in `set_item_model`). Tests: `test/sam3d.test.ts` (fake fal queue). The `SAM3D_MAX_USD` cap is per `SAM3D_SPEND_WINDOW_H` (24 h): on start it re-counts `costUsd` from this agent's `agent_event` tool calls, so supervisor restarts don't reset it.
- `src/agents/sam3d.ts` + `src/integrations/sam3d.ts` (#65, #84): items with `model_status = pending`, a photo, vision done/failed and no captured model get a 3D model from **Meta SAM 3D Objects** on fal.ai (`fal-ai/sam-3/3d-objects`, queue REST API, `export_textured_glb`), built from **the best available image**, not just the latest photo:
  1. **Candidates:** the item's own photos (the first photo of a scanned item counts as the scan crop, the rest as user photos; up to 5). If vision identified a specific product (`isSpecificProduct`: a brand, or a model-number-like token in the name), also up to `SAM3D_WEB_IMAGES_MAX` (6) web images for the pricing query (brand + name): listing photos from the cached comps (free; `apify.ts` now keeps each comp's `imageUrl`, which older caches lack and `add_comps` never gets) and a Google Images search on Apify (`hooli~google-images-scraper`, `{queries, maxResultsPerQuery}`, ~$0.0035/image, `maxItems` + `maxTotalChargeUsd = SAM3D_IMAGE_SEARCH_MAX_USD`), cached in `fixtures/product-images/<slug>.json` and replayed with `[REPLAYED]`. Web images are downloaded by `loadWebImage` (`src/integrations/product-images.ts`): https only, every resolved address public (same checks as `photos.ts`), no redirects, optional `PRODUCT_IMAGE_HOSTS` allowlist, 4.5 MB / 15 s caps, and the bytes must be a JPEG/PNG/WebP.
  2. **Choose** (`src/agents/sam3d-select.ts`): Claude (`MODEL_VISION`, effort low) scores every image 0-10 for single-image reconstruction of this exact item (whole object, unoccluded, three-quarter angle, plain background), flags web images of a different product, and gives a box as fractions (converted to SAM 3D pixel `box_prompts` with the header size from `imagesize.ts`). Web titles go in an `<untrusted>` block and the system prompt carries `UNTRUSTED_RULE`; text inside images is data. Code decides eligibility, so a fooled model can't push another product: own photos are always eligible, web images only if `sameProduct` and score >= 5. One own photo and nothing else skips Claude. If Claude fails, it uses own photos newest first and no web images.
  3. **Generate:** SAM 3D on the best image (with its box), and on failure the next-best, up to `SAM3D_MAX_ATTEMPTS` (2). The GLB goes to `uploads/<uuid>.glb` (served at `/files/`, never accepted as an upload), then `set_item_model(url, 'sam3d')`.
  Events: `plan`, a `tool_call` for the image search (cost), the pick (cost) and each fal attempt (cost, attempt, source), a `result` for the pick (`chosen`, `ranking`, `rejected`) and the model, and an `error` per failure. Every step's `data` names the image's `source` (`scan` | `user` | `web`, plus `webSource`/`imageUrl`/`page` or `photoIndex`). `SAM3D_MAX_USD` (default $2 per worker run) covers fal (`SAM3D_USD_PER_RUN`, $0.02), picks (`SAM3D_SELECT_USD`, $0.04 estimate) and searches; each step is skipped (logged with `refused: true`) when what's left can't also pay for a fal run. `add_item_photo` re-queues the item (vision first, then the model, so the new photo is re-ranked); a photo added mid-build is caught and the item is put back to pending after the build. `SAM3D_WEB_IMAGES=0` turns the web off. If fal refuses the request itself (401/402/403 such as "Exhausted balance", 429, 5xx: `Sam3dUnavailableError`), the item goes back to `pending` without trying the next image, the attempt isn't counted against the cap, and it's retried after `SAM3D_RETRY_LATER_SEC` (600) or on a new photo. Without `FAL_KEY` the agent is off and items stay pending. Object Capture models from the phone always win (enforced in `set_item_model`). Tests: `test/sam3d.test.ts` (fake fal queue), `test/sam3d-select.test.ts` (ranking, boxes, prompt hygiene, image search, web image loader), `test/sam3d-agent.test.ts` (the build against a fake connection: web pick, retry, fallbacks, spend cap, mid-build photo).
- `scripts/e2e.ts` (`npm run e2e [-- --replay | --live] [-- --keep]`): end-to-end pipeline test on a **local** SpacetimeDB (`spacetime start`). It publishes the current module to a fresh `moove-e2e`, starts its own worker on spare ports (8790 uploads, 8412 x402), then drives the app's reducers as a normal user: `import_scan_v2` → pricing (x402 simulated) → sort → room photo sweep → listing + approval → new home → shopping list → deals + fraud → purchase + approval (simulated Visa), then the commerce guarantees: x402 calls past a tight $0.05 pricing budget are refused before paying (no payment row, pricing falls back), a card deal over the $200 buy card budget and a planted Zelle-scam card deal (scored by the real fraud screen, planted via the worker token since `add_deal` is worker-only) are refused with no approval and no charge, and every `payment` row is complete and `simulated: true` with `[SIMULATED]` payment events. `E2E_URI` / `E2E_DB` / `E2E_UPLOAD_PORT` / `E2E_X402_PORT` pick another server, DB and ports (it publishes to the server `E2E_URI` names). Prints a PASS/FAIL table and exits non-zero on failure. Safe by default even with `.env.local` loaded: `LLM_REPLAY=replay` (a miss fails, never calls Claude; opt in with `E2E_LLM=auto|record` or `--live`), `X402_SIMULATE=1` (opt in to real Base Sepolia payments with `E2E_REAL_X402=1`), simulated Visa, and Apify/fal are never called. The worker stage and the table header print the modes that ran. Add a stage whenever you add an agent.
- `scripts/status.ts` (`npm run status [-- moove moove-demo] [-- --uri ws://localhost:3000]`): checks each backend as an anonymous client (worker version and start time from `service_config`, upload URL `/healthz`, row counts, newest agent event, errors in the last hour). Exits non-zero if one is down. Backends are listed in `docs/backends.md`.
